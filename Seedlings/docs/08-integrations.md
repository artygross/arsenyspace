# 08 — Карта интеграций

Статусы: **Обязательно** — без этого первая версия не работает. **Опционально** — включается по
подтверждению клиента. Вне объёма по брифу: МойСклад, 1С, Telegram-бот, CRM.

| Система | Статус | Роль |
|---|---|---|
| Сайт (Next.js) | Обязательно | Витрина, корзина, чекаут, ЛК. Здесь формируется заказ |
| БД сайта (PostgreSQL) | Обязательно | Заказы, товары, покупатели, промокоды. **Источник истины по заказу** |
| Email (SMTP-провайдер) | Обязательно | Все уведомления покупателю и магазину |
| Бизнес.ру | Обязательно | Учёт: остатки, цены, документы, накладная |
| Расчёт доставки | Обязательно | Тарифная таблица по зонам внутри сайта |
| Служба доставки по API | Опционально | Автосоздание отправления. Только после подтверждения перевозчика |
| Онлайн-оплата (ЮKassa) | Опционально | Если клиент готов подключать эквайринг |
| Онлайн-чеки (54-ФЗ) | Опционально | Нужны только при онлайн-оплате. У Бизнес.ру есть отдельный API онлайн-чеков |
| Яндекс.Метрика + ecommerce | Обязательно | Аналитика воронки |

## 1. Поток данных: где что рождается

```
Бизнес.ру ──остатки, цены, номенклатура──▶ БД сайта ──▶ витрина
   ▲                                          │
   └──заказ (документ «Заказ покупателя»)──────┘
                                              │
                                              ├──▶ Email покупателю (подтверждение + накладная)
                                              ├──▶ Email магазину (новый заказ)
                                              └──▶ PDF-накладная (генерируется сайтом)
```

**Правило:** заказ формируется **на сайте**, в БД сайта, и только потом выгружается в Бизнес.ру.
Обратное направление (заказ рождается в учётке) не рассматривается — сайт не может зависеть от
доступности внешнего сервиса в момент оформления.

## 2. Синхронизация с Бизнес.ру

| Направление | Что передаётся | Когда | Что при отказе |
|---|---|---|---|
| Бизнес.ру → сайт | Номенклатура, цены, остатки, статусы партий | Каждые 15 мин (cron) + ручная кнопка в админке | Сайт торгует последним успешным снимком; в админку падает алерт |
| Сайт → Бизнес.ру | Заказ покупателя: позиции, количества, цены, скидка, промокод, покупатель, способ получения, адрес | Сразу после оформления, асинхронно, с очередью и ретраями | Заказ уже принят и лежит в БД сайта; задача висит в очереди и повторяется. Покупатель ничего не замечает |
| Сайт → Бизнес.ру | Отмена / изменение заказа | По событию | То же |
| Бизнес.ру → сайт | Смена статуса заказа (собран, отгружен) | Опрос раз в 10 мин | Статус в ЛК не меняется, заказ не теряется |

**Соответствие сущностей:** товар сайта ↔ номенклатура (связь по внешнему коду/артикулу, не по имени);
фасовка (кассета/P9/ОКС) ↔ отдельная позиция номенклатуры со своим артикулом — так остаток считается
правильно; заказ ↔ документ «Заказ покупателя»; покупатель ↔ контрагент.

## 3. Как клиенту получить API-доступ к Бизнес.ру

1. **Действующий аккаунт Бизнес.ру** с оплаченным тарифом, где включён программный модуль
   «Бизнес.API» (интеграция по API). Права — у владельца аккаунта или администратора.
2. В аккаунте: **Настройки → Маркетплейс → виджет «Интеграция по API»**. В форме настройки
   интеграции создаётся интеграция и выдаются два значения: **Id интеграции (`app_id`)** и
   **Секретный ключ**.
3. Клиент передаёт разработчику `app_id` и секретный ключ **защищённым каналом** (не в мессенджер
   и не в почту). Ключ хранится только в переменных окружения сервера, в репозиторий не попадает.
4. Авторизация запросов — по `app_id` + подпись запроса секретным ключом (`app_psw`) и
   циклически обновляемому токену; обмен идёт по HTTPS. Точная схема подписи и порядок обновления
   токена берутся из официальной документации и SDK на **developers.business.ru** — там же лежат
   Postman-коллекция и PHP-SDK, по которым сверяется реализация.
5. **Что ещё понадобится от клиента:**
   - название организации/склада в Бизнес.ру, откуда списывать остатки;
   - справочник номенклатуры с заполненными артикулами (иначе связывать товары не с чем);
   - тип документа, которым оформляется заказ с сайта, и его статусы;
   - тестовый (или отдельный) аккаунт для отладки, чтобы не сорить в боевом учёте;
   - контакт технической поддержки Бизнес.ру на стороне клиента.
6. **Проверка перед разработкой:** сделать один тестовый запрос списка номенклатуры и один
   тестовый заказ. Если модуль API не входит в тариф клиента — это платное расширение,
   и решается до старта разработки, а не в конце.

> Если API-доступ по какой-то причине не появится, запасной путь — обмен CSV/XML-выгрузками по
> расписанию. Он хуже (задержка, ручные ошибки), но не блокирует запуск сайта.

## 4. Email-уведомления: полный перечень

| Событие | Кому | Что внутри |
|---|---|---|
| Заказ оформлен | Покупателю | Номер, состав, сумма, способ получения, адрес/самовывоз, **накладная PDF**, памятка по первому дню |
| Заказ оформлен | Магазину | Состав, контакты, комментарий, способ получения |
| Заказ собран / готов к выдаче | Покупателю | Дата и адрес выдачи, часы работы, срок хранения |
| Заказ отгружен | Покупателю | Трек-номер, срок в пути, памятка «что делать при получении» |
| Предзаказ: партия пришла | Покупателю | Ссылка на оплату/подтверждение |
| «Сообщить о поступлении» | Подписчику | Товар снова в наличии |
| Брошенная корзина (опционально) | Покупателю | Через 24 ч, с составом корзины |
| Промокод сезона (опционально) | Подписчикам | Рассылка по базе |

Технически: транзакционная почта через SMTP-провайдера с подтверждённым доменом
(SPF, DKIM, DMARC — иначе письма уходят в спам). Отправка — из очереди, с ретраями и логом.

## 5. Самовывоз

Отдельный способ получения, не «доставка за 0 ₽»:

- на витрине и в чекауте показывается адрес, часы работы, дата готовности заказа;
- стоимость 0 ₽, поля адреса скрываются, телефон обязателен;
- статус заказа `готов к выдаче` → письмо покупателю с датой и сроком хранения;
- в накладной пункт выдачи указан явно;
- в Бизнес.ру заказ уходит с признаком самовывоза и складом выдачи.

## 6. Расчёт доставки

Первая версия — **тарифная таблица по зонам** внутри сайта, без внешних API:
зона (город питомника / область / соседние регионы / остальная Россия) × вес заказа,
плюс порог бесплатной доставки и сезонная надбавка на термоупаковку.
Это честно, предсказуемо и не ломается, когда у перевозчика лежит API.

Подключение API перевозчика — вторая волна и **только опционально**: у живых растений
особые условия перевозки, и тариф из калькулятора общего назначения может оказаться неверным.
СДЭК Pay в решение не закладывается (требование брифа).

## 7. Автоматическая накладная

Генерируется сайтом в момент оформления: номер и дата, продавец с реквизитами, покупатель,
позиции (артикул, сорт, фасовка, количество, цена, сумма), скидка и промокод, доставка, итог
прописью, способ получения, подписи. Форма — печатная HTML-страница `/order/[id]/invoice`
(печать в PDF из браузера) + вложение в письмо. Дублируется документом в Бизнес.ру.

## 8. Аналитика

Яндекс.Метрика с электронной коммерцией: `view_item`, `add_to_cart`, `begin_checkout`, `purchase`.
Дополнительно свои цели: применён промокод, выбран самовывоз, открыт блок «Посадка и уход»,
подписка «сообщить о поступлении». Последняя — метрика несезонного трафика, по ней планируется закупка партии.
