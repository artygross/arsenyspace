# 11 — Выкладка на Netlify

Цель этой выкладки — показать клиенту работающий прототип для согласования, а не запустить
магазин в продажу. Поэтому данные остаются демонстрационными, а индексация закрытой.

## Что уже готово в репозитории

| Элемент | Где | Состояние |
|---|---|---|
| Приложение | `Seedlings/site` | Пакет pnpm-воркспейса `seedlings-site` со своим `package.json` |
| Конфиг сборки | `Seedlings/site/netlify.toml` | Команда, publish, версия Node, заголовки безопасности |
| Ветка | `seedlings` | Отдельная от `main`, где живёт магазин очков |
| Индексация | `Seedlings/site/app/robots.ts` | `Disallow: /` — прототип не должен попасть в поиск |

## Настройки проекта в Netlify

1. **Add new project → Import an existing project → GitHub → репозиторий `arsenyspace`.**
2. **Branch to deploy:** `seedlings` (не `main` — там магазин очков).
3. **Base directory:** оставить пустым (корень репозитория). Оттуда ставятся зависимости
   всего pnpm-воркспейса, включая пакет сайта.
4. **Package directory:** `Seedlings/site`. Это указывает Netlify, какой пакет собирать
   и где искать `netlify.toml`.
5. **Build command и Publish directory** подставятся из `netlify.toml`
   (`pnpm --filter seedlings-site build`, `.next`) — менять не нужно.
6. **Deploy.** Первая сборка ставит зависимости с нуля, дальше работает кэш.

Если в интерфейсе нет поля Package directory (оно доступно в настройках проекта после создания),
можно задать **Base directory = `Seedlings/site`** — конфиг будет найден там же, а pnpm сам
подтянет воркспейс из корня. Обе схемы рабочие, команда сборки от места запуска не зависит.

## Проверить после первого деплоя

- [ ] Главная, каталог, карточка сорта, корзина, чекаут, накладная открываются
- [ ] Шрифты подгрузились (Manrope в заголовках), иначе смотрите лог: сборке нужен доступ к fonts.googleapis.com
- [ ] `/robots.txt` отдаёт `Disallow: /`
- [ ] `/sitemap.xml` отдаёт список маршрутов (нужен для приёмки, не для индексации)
- [ ] На мобильном нет горизонтального скролла

## Что сказать клиенту при показе

Это прототип для согласования: структура, логика и тексты настоящие, а каталог, цены, остатки,
отзывы и реквизиты — демонстрационные. Что нужно от клиента, чтобы прототип стал магазином,
перечислено в `09-questions.md`; что и в каком порядке подключается дальше — в `07-handoff.md`.

## Ограничения демо-режима

- Корзина, избранное, заказы и отзывы живут в браузере посетителя (localStorage). У каждого
  свой набор данных, между устройствами они не переносятся — это ожидаемо до появления бэкенда.
- Письма не отправляются: формы подтверждают отправку в интерфейсе, точки подключения описаны
  в `08-integrations.md` §4.
- Накладная открывается только у того, кто оформил заказ в этом браузере.
- Даты отгрузки заданы константами в `lib/catalog.ts` (`SHIPMENT`) — при показе в другом месяце
  их стоит подвинуть, иначе «сезон» будет выглядеть странно.
