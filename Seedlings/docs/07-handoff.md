# 07 — Handoff (передача в разработку)

## 1. Как запустить

```bash
pnpm dev:seedlings     # http://localhost:3210
pnpm build:seedlings   # продовая сборка
pnpm lint:seedlings
pnpm start:seedlings   # затем в другом терминале:
pnpm check:seedlings   # вёрстка + сценарии в headless-браузере
```

Сайт рассады — отдельное Next-приложение в `Seedlings/site`, живёт на ветке `seedlings`.
Магазин очков в корне репозитория не тронут: он остаётся на `main` и запускается своими
командами `pnpm dev` / `pnpm build`. Общий `node_modules` — Next разрешает пакеты вверх по дереву.

## 3. Точки подключения бэкенда

| Что | Где сейчас | Что делать |
|---|---|---|
| Каталог | `getProducts()` в `lib/catalog.ts` возвращает статический массив | Заменить на запрос к БД сайта, которую наполняет синхронизация с Бизнес.ру. Форма `Product` остаётся |
| Наличие и даты отгрузки | Поля `availability`, `shipsFrom`, `stockLeft` | Приходят из учётной системы; правило трёх статусов не меняется |
| Заказ | `saveOrder()` в `lib/orders.ts` пишет в localStorage | Заменить на server action → запись в БД → очередь на выгрузку в Бизнес.ру |
| Промокоды | `PROMOS` в `lib/promo.ts` | Таблица в БД с лимитами и счётчиком использований; проверка на сервере обязательна |
| Доставка | `quoteDelivery()` | Тарифы вынести в БД, расчёт оставить на сервере |
| Email | `SubscribeForm`, `NotifyForm`, оформление заказа | Транзакционная почта из очереди, SPF/DKIM/DMARC. Перечень писем — `08-integrations.md` §4 |
| Накладная | `/invoice/[id]`, читает localStorage | Серверный рендер по id заказа + PDF во вложение письма |
| Отзывы | `components/product-reviews.tsx`, localStorage | API с модерацией и загрузкой фото |
| Фотографии | `site/public/photos/`, `lib/photos.generated.ts`, `scripts/photo-manifest.mjs` | Файл с именем по слагу сорта → фото подхватывается везде; где фото нет, остаётся иллюстрация |
| Логотип | `COMPANY.logo` и `COMPANY.logoMark` в `lib/content.ts`, файлы в `public/logo/` | Подключён. Новый исходник — в `Seedlings/assets/logo-source.png`, затем `node Seedlings/scripts/logo-prep.mjs`: пересоберёт оба размера и иконки |
| Импорт из ВК | `scripts/vk-import.mjs` | Название, товары, описания, цены и фото сообщества через официальный API (нужен токен) |
| Кабинет | Данные из последнего заказа | Вход по одноразовому коду из письма |

## 4. Что нельзя ломать при доработке

1. **Три статуса наличия.** Булев `inStock` в этой нише неверен: `preorder` и `out_of_season`
   несут разный интерфейс и разные письма.
2. **Фильтры в URL.** Любой новый фасет добавляется в `parseQuery` / `toSearchParams` — иначе
   выдача перестанет шариться и индексироваться.
3. **Счётчики фасетов считаются без учёта самого фасета** (`countFor(skip)`), иначе выбор
   схлопывает список в один пункт.
4. **Цена никогда не показывается без даты отгрузки** — правило поведения №8.
5. **Фасовка — отдельный SKU.** `resolveSku()` разбирает `slug--container`; связь с номенклатурой
   Бизнес.ру идёт по артикулу, не по названию.
6. **Промокод проверяется на сервере.** Клиентский расчёт — только предпросмотр.

## 5. Приоритеты (ответ на п. 6 брифа)

**Волна 1 — первая версия (сделано):** каталог с фасетами, карточка, корзина, чекаут с самовывозом,
промокоды, расчёт доставки, автонакладная, избранное, кабинет, поиск, акции, отзывы, сезонные статусы,
email-уведомления (точки подключения готовы), SEO-каркас.

**Волна 2 — сделано:** сравнение сортов, тематические подборки `/collection/[slug]`,
статьи `/care/[slug]` под поисковый трафик, микроразметка Product / FAQPage / Article / BreadcrumbList / ItemList.

**Волна 2 — осталось:** брошенная корзина, фото в отзывах, онлайн-оплата, API перевозчика,
личный кабинет с входом по коду, админка контента.

**Заложено архитектурно заранее:** трёхзначное наличие и даты отгрузки, отдельные SKU по фасовкам,
структура заказа под выгрузку в учётную систему, очередь писем, фасеты, расширяемые без переписывания
каталога, параметрические иллюстрации с заменой на фото, `metadataBase` и sitemap под боевой домен.

## 6. Деплой

`Seedlings/site/netlify.toml` готов, приложение оформлено пакетом pnpm-воркспейса `seedlings-site`.
В панели Netlify: импорт репозитория → **Branch = `seedlings`**, **Base directory** оставить корнем,
**Package directory = `Seedlings/site`**. Пошагово, вместе с чек-листом проверки после деплоя
и списком ограничений демо-режима, — в `11-deploy-netlify.md`.

Альтернатива, если сайт рассады должен жить в корне ветки: перенести содержимое
`Seedlings/site` в корень (`git mv`) и удалить код магазина очков на этой ветке — он останется на `main`.

## 7. Чек-лист перед боевым запуском

- [ ] Снять `Disallow: /` в `app/robots.ts`, подставить боевой домен в `metadataBase`, `sitemap.ts` и `structured-data.tsx`
- [ ] Проверить микроразметку в Rich Results Test после открытия индексации
- [ ] Заменить демо-каталог реальной выгрузкой, проверить артикулы
- [ ] Подставить реквизиты, телефон, адрес самовывоза, оферту и политику ПДн
- [ ] Подключить Бизнес.ру: `app_id`, секретный ключ, склад, тип документа заказа
- [ ] Настроить транзакционную почту и проверить доставляемость (SPF/DKIM/DMARC)
- [ ] Перенести тарифы доставки в БД и сверить с реальными договорами
- [ ] Завести промокоды с лимитами и проверкой на сервере
- [ ] Заменить иллюстрации на фотосъёмку (сорт, корневая система, урожай)
- [ ] Подключить Яндекс.Метрику с электронной коммерцией
- [ ] Проверить на реальных устройствах и в Safari, прогнать скринридером
