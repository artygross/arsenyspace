# 02 — Analysis (разбор бизнес-логики)

## 1. Чем эта ниша отличается от обычного e-commerce

Четыре отличия задают почти всю архитектуру:

1. **Товар живой.** Главный барьер покупателя — не цена, а «дойдёт ли живым и приживётся ли».
   Отсюда: блок доверия не украшение, а функция; гарантия приживаемости — обязательный элемент оферты.
2. **Товар сезонный.** Один и тот же SKU весной — «в наличии», летом — «предзаказ на осень»,
   зимой — «сезон закрыт». Статус наличия должен быть трёхзначным, а не булевым.
3. **Покупают набором и по назначению.** Никто не покупает «один саженец малины». Покупают
   «малину на всё лето»: ранний + средний + ремонтантный сорт. Отсюда — подборки и допродажа комплектом.
4. **Покупатель сравнивает сорта, а не бренды.** Бренда у рассады нет. Есть характеристики сорта:
   срок созревания, зимостойкость, урожайность, размер ягоды, шипы, ремонтантность.
   Эти поля должны быть структурированными, а не текстом в описании — иначе не работают ни фильтры, ни сравнение.

## 2. Модель товара

```ts
type Product = {
  slug, name, culture, kind,            // культура (малина) и подтип (ремонтантная)
  ripening: early | mid | late | everbearing,
  container: cassette | p9 | pot1l | okc, // фасовка/корневая система
  packSize: number,                      // штук в упаковке
  price, oldPrice?,                      // ₽ за упаковку
  availability: in_stock | preorder | out_of_season,
  stockLeft, shipsFrom,                  // партия и дата ближайшей отгрузки
  hardiness: number,                     // зимостойкость, °C
  yieldPerBush, berrySize, sun, height,  // агрономические характеристики
  plantingWindow: [месяц, месяц],        // окно посадки
  isNew, isHit, rating, reviewCount,
  short, description, care[],            // уход — 3–5 шагов, снимает страх
  reviews[]
}
```

**Решение D-05:** агрономические характеристики — отдельные типизированные поля, а не строка.
Один и тот же массив кормит фильтры, таблицу характеристик в карточке и сниппет в выдаче.

## 3. Статусы наличия (ядро сезонной логики)

| Статус | Что видит покупатель | Что делает кнопка | Когда |
|---|---|---|---|
| `in_stock` | «В наличии, отгрузка с 15 апреля» | В корзину | Сезон открыт, партия есть |
| `preorder` | «Предзаказ на осень 2026, отгрузка с 5 сентября» | Оформить предзаказ | Партия ещё не выкопана |
| `out_of_season` | «Сезон закрыт, вернётся в апреле» | Сообщить о поступлении (email) | Вне окна отгрузки |

**Решение D-06:** товар вне сезона не скрывается из каталога. Он остаётся индексируемой страницей
с формой подписки — иначе сайт теряет весь несезонный поисковый трафик и половину email-базы.

## 4. Сценарии

**S-1. Новичок из ВК, мобильный.** Заходит по ссылке из поста → главная → «Клубника» →
каталог, отфильтрован по культуре → карточка сорта → блок «когда сажать / как ухаживать» →
в корзину → чекаут в 1 экран → email с накладной. Ключ: не заставлять регистрироваться.

**S-2. Осознанный садовод.** Идёт в каталог, фильтрует: культура = малина, тип = ремонтантная,
срок = поздний, зимостойкость до −30. Сравнивает 2–3 сорта по характеристикам. Ключ: фасетные фильтры и характеристики.

**S-3. Возвратный покупатель.** Личный кабинет → «Мои заказы» → «Повторить заказ». Ключ: скорость.

**S-4. Самовывоз.** Живёт рядом с питомником, хочет посмотреть растение вживую.
Чекаут с самовывозом: доставка 0 ₽, адрес и часы работы, дата готовности заказа.

## 5. Экономика решений

| Развилка | Выбор | Почему |
|---|---|---|
| Гостевой чекаут vs обязательная регистрация | Гостевой, аккаунт создаётся автоматически по email | Регистрация до оплаты убивает 20–30 % конверсии, а аудитория 45+ особенно чувствительна |
| Цена за штуку vs за упаковку | За упаковку, с явной подписью «5 шт. в упаковке — 78 ₽/шт.» | Эконом-сегмент считает цену за штуку, но продажа поштучно нерентабельна |
| Скрывать несезонный товар | Не скрывать | SEO и сбор email-базы к сезону |
| Отзывы | Обязательны с первой версии | В нише «живой товар» отзыв — главный аргумент, дороже любого текста о качестве |
| Сравнение сортов | Вторая волна | Полезно, но фильтры + характеристики в карточке закрывают 80 % задачи дешевле |

## 6. Ограничения объёма (из брифа)

Вне решения: МойСклад, 1С, Telegram-бот, CRM. СДЭК Pay не закладывается.
Всё, что не подтверждено клиентом, помечается опциональным и вынесено в `08-integrations.md` отдельной колонкой.
