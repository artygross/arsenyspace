# 07 — Handoff (передача в разработку)

Документ описывает, что сделано, как это устроено и что нужно сделать, чтобы превратить прототип в боевой магазин.

## 1. Состав

**Приложение:** Next.js 16.3.2 (App Router, Turbopack) · React 19.2 · TypeScript · Tailwind CSS v4.
**Пакетный менеджер:** pnpm 11.8.

## 2. Архитектура в трёх предложениях

Весь каталог — один модуль `src/lib/catalog.ts`: модель товара, данные, предикаты фильтрации, подсчёт фасетов и текстовый поиск. Экраны каталога, поиска и страницы бренда — это один и тот же серверный компонент `CatalogView`, отличающийся только подмножеством товаров и скрытыми фасетами. Всё, что должно пережить перезагрузку на стороне пользователя (корзина, избранное, сравнение, отзывы, результат подбора), лежит в четырёх однотипных внешних хранилищах поверх `localStorage`.

### Что читать первым
1. `docs/02-analysis.md` — зачем всё устроено именно так, модель данных товара.
2. `src/lib/catalog.ts` — единственный источник правды по товарам.
3. `docs/05-ui-system.md` — токены и правила поведения интерфейса.

## 3. Подключение реального источника данных

**Точка одна:** массив `PRODUCTS` в `src/lib/catalog.ts`.

Публичные функции модуля — `filterProducts`, `facetCount`, `getProduct`, `similarTo`, `suggest`, `searchScore` — работают поверх переданного или дефолтного списка. Замена источника не требует правок ни в одном экране:

```ts
// было
export const PRODUCTS: Product[] = [ ...мок-данные... ];

// станет
export async function getProducts(): Promise<Product[]> { ... }
```

**Что придётся поправить при переходе на асинхронный источник:**
- `PRODUCTS`, `BRANDS`, `FRAME_COLORS`, `LENS_COLORS`, `PRICE_MIN/MAX` сейчас вычисляются на этапе модуля — станут функциями или кэшем.
- `generateStaticParams` в `product/[slug]` и `brands/[brand]` станет `async`.
- `buildFacets` в `src/components/catalog-view.tsx` уже принимает базовый список параметром — менять не нужно.

**Обязательные поля товара** перечислены в типе `Product`. Критичные для UX и не всегда присутствующие в типовых выгрузках:
- `dimensions` (`52□18-145`) — на них держится вся работа с посадкой;
- `faceShapes` — связывает квиз подбора с каталогом;
- `variants` — пары «цвет оправы × цвет линзы», от них зависят свотчи и галерея.

Без `faceShapes` квиз подбора перестанет работать; это вычисляемый атрибут, его нужно либо завести в PIM, либо выводить из формы оправы правилом.

## 4. Перенос локальных хранилищ на сервер

Четыре модуля написаны по одному шаблону: `useSyncExternalStore` + `localStorage` + событие `storage` для синхронизации вкладок.

| Модуль | Ключ в localStorage | Что хранит |
|---|---|---|
| `components/cart.ts` | `optika:cart:v1` | позиции корзины |
| `components/wishlist.ts` | `optika:wishlist:v1` | избранное |
| `components/compare.ts` | `optika:compare:v1` | шорт-лист сравнения |
| `components/reviews.ts` | `optika:reviews:v1` | отзывы пользователя с фото |
| `components/finder-store.ts` | `optika:finder:v1` | результат подбора |

**Как мигрировать:** заменить `readStorage()` и `write()` на запросы к API, оставив `subscribe`/`getSnapshot`/`getServerSnapshot` и сигнатуры хуков. Экраны не трогаются.

**Важно про `getServerSnapshot`.** Он возвращает пустое состояние — так задумано: на сервере корзины ещё нет, а расхождение с разметкой при гидратации привело бы к ошибке. Флаг `ready` отличает «пусто» от «ещё не прочитали». При переезде на сервер `getServerSnapshot` должен отдавать реальные данные сессии, иначе `ready` останется нужен.

**Отзывы.** Фото ужимаются в браузере до 320 px и JPEG 0.7 (`shrinkImage` в `components/reviews.ts`) — иначе переполняется квота `localStorage`. При переезде на сервер сжатие лучше сохранить как предварительное, но добавить серверную валидацию: сейчас файл проверяется только по MIME из `accept`.

## 5. Дизайн-система

Все токены — в `src/app/globals.css`, блок `@theme`: палитра, шрифты, утилиты `shell` (сетка), `section` (вертикальный ритм), `eyebrow`.

Смена бренда — это правка восьми цветовых переменных и двух шрифтов в `layout.tsx`. Компоненты цвета не хардкодят.

Правила поведения интерфейса (URL как источник правды для фильтров, валидация по blur, видимый фокус, уважение `prefers-reduced-motion` и прочие) перечислены в `docs/06-design-execution.md` с указанием, где каждое реализовано.

### Изображения товара
Оправа рисуется параметрически: `components/glasses.tsx` принимает форму, цвет оправы и цвет линзы из модели товара. Один компонент обслуживает карточку, галерею PDP, миниатюры, корзину, панель сравнения и пиктограммы фасета «Форма оправы».

При замене на фотосъёмку меняется один компонент. Требования к съёмке, чтобы вёрстка не поехала:
- соотношение сторон **4:5** для карточки каталога и **4:3** для галереи PDP;
- по кадру на каждую вариацию `variant` — иначе свотч цвета и картинка разойдутся;
- нейтральный фон, совпадающий с токеном `--color-surface-alt` (`#f4f2ef`).

## 6. Деплой на Netlify

Netlify определяет Next.js автоматически и собирает проект своим OpenNext-адаптером. Адаптер намеренно **не закреплён версией** в `package.json` — Netlify обновляет его под каждый релиз Next.js, а закрепление отключает эти обновления.

### Первый деплой
1. Запушить репозиторий в Git-провайдера (GitHub / GitLab / Bitbucket).
2. В панели Netlify: **Add new project → Import an existing project**, выбрать репозиторий.
3. Настройки сборки подхватятся из `netlify.toml`; ничего вводить вручную не нужно.
4. Deploy.

### Что уже настроено (`netlify.toml`)
- команда сборки `pnpm build`;
- `NODE_VERSION = "22"` — воспроизводимость сборки;
- заголовки безопасности: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`.

### Что нужно знать
- **Сборке нужен интернет.** `next/font/google` скачивает Inter и Playfair Display на этапе сборки и инлайнит их. В закрытом контуре сборка упадёт — тогда шрифты нужно положить в `public/` и перейти на `next/font/local`.
- **Индексация закрыта.** `src/app/robots.ts` отдаёт `Disallow: /`, потому что бренды, цены и наличие вымышлены. Для боевого запуска — заменить правило на `allow: "/"` и добавить `src/app/sitemap.ts`.
- **Динамические маршруты** (`/catalog`, `/search`, `/compare`, `/brands/[brand]`) рендерятся на сервере при каждом запросе — они читают параметры URL. Остальные 43 страницы, включая все 24 карточки товара, отдаются статикой.
- **Версия Node.** Локально сборка проверена на Node 24, в `netlify.toml` закреплена 22. Обе удовлетворяют требованию Next.js (`>=20.9`), но первую сборку на Netlify стоит просмотреть на предмет предупреждений.
- **Ничего не требует переменных окружения.** Приложение самодостаточно: нет внешних API, ключей и баз.

### После появления бэкенда
Появятся переменные окружения — задавать их в **Project configuration → Environment variables**, не в `netlify.toml` (файл в репозитории, секретам там не место).
