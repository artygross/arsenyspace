## Зафиксированные решения

| ID | Решение | Обоснование |
|---|---|---|
| D-01 | Только солнцезащитные очки, оптика с диоптриями вне объёма | Ответ на интервью. Убирает конфигуратор линз и ввод рецепта из чекаута |
| D-02 | Модель — мультибренд-ритейлер B2C | Ответ на интервью. Делает фильтр по бренду и доверие к подлинности первоклассными задачами |
| D-03 | Платформа — Next.js в текущем репозитории | Ответ на интервью. Макеты проектируются под реальные компоненты |
| D-04 | Равный приоритет mobile / desktop | Ответ на интервью. Ядро сделки макетируется в двух брейкпоинтах |
| D-05 | Каталог 300—1000 моделей | Ответ на интервью. Требует фасетных фильтров и автокомплита в поиске |
| D-06 | Рынок РФ, русский, ₽ | Ответ на интервью. Мультиязычность и мультивалютность не закладываются |
| D-07 | Визуальный тон — премиальный fashion | Ответ на интервью. Задал палитру, нулевые радиусы, отсутствие теней, дисплейную антикву |
| D-08 | В объёме: подбор по форме лица, сравнение, отзывы | Ответ на интервью. Все три — ответы на барьер «подойдут ли мне» |
| D-09 | AR-примерка вне объёма | Ответ на интервью. Требует 3D-контента, не оправдана на старте |
| D-10 | Нижняя таб-панель на mobile не используется | Конфликтует с премиальным тоном и съедает высоту у крупных фото |
| D-11 | Результат квиза = предфильтрованный каталог, не список из 3 моделей | Сохраняет свободу выбора и переиспользует систему фильтров |
| D-12 | Состояние фильтров пишется в URL | Шарящиеся и индексируемые выдачи |
| D-13 | Этап 6 — сразу компоненты Next.js, без промежуточного канваса | Решение пользователя. Макет и код — один артефакт, правки идут в одном месте |
| D-14 | Изображения товара — параметрический SVG, а не фото | Фотоконтента нет. Один компонент кормится моделью товара, поэтому свотч цвета и картинка не могут разойтись |
| D-15 | Бренды в каталоге вымышленные | Демонстрационные данные не должны использовать чужие торговые марки |
| D-16 | Квиз подбора вытянут из волны 2 в волну 1 | Переиспользует систему фильтров — дёшев, а без него ключевой дифференциатор остался бы только на бумаге |
| D-17 | Корзина хранится вне React, в localStorage | Переживает навигацию, синхронизируется между вкладками, читается без эффекта на монтировании |
| D-18 | Допродажа в корзине — вторая пара очков, а не аксессуары | Футляры и уход не входят в модель данных (D-01 ограничил ассортимент). Требует решения по ассортименту аксессуаров |
| D-19 | Список сравнения живёт в URL `?items=`, а не только в хранилище | Сравнением делятся — ссылка должна открываться у другого человека. Побочно таблица рендерится на сервере |
| D-20 | Текстовый поиск — предикат внутри `Query`, а не отдельная подсистема | Запрос и фасеты складываются без дублирования кода; `/search` переиспользует вид каталога целиком |
| D-21 | Фото в отзывах ужимаются до 320 px / JPEG 0.7 перед записью | Пара снимков с телефона переполнила бы квоту `localStorage` на первом же отзыве |
| D-22 | Добавлено избранное | Иконка сердца была в спецификации карточки (`05-ui-system.md`), но пропущена в первой волне — это исправление упущения, а не новая фича |
| D-23 | У брендов собственный маршрут `/brands/[slug]`, фасет «Бренд» на них скрыт | На странице бренда он предопределён; возможность его снять ломала бы идентичность страницы |
| D-24 | Результат подбора сохраняется и попадает в кабинет | Иначе квиз одноразовый: пользователь не может вернуться к своей подборке |
| D-25 | Деплой — Netlify, OpenNext-адаптер, версия адаптера НЕ закрепляется | Netlify обновляет адаптер под каждый релиз Next.js; закрепление версии отключает эти обновления |
| D-26 | Индексация закрыта (`robots.ts` → `Disallow: /`) | Бренды, цены и наличие вымышлены — карточки несуществующих товаров не должны попадать в поисковую выдачу. Снимается одной строкой при боевом запуске |
| D-27 | Фасеты применяются с оптимистичным состоянием | Фильтр идёт через URL, то есть через сервер. Без этого отметка в чекбоксе появлялась только после ответа — нарушение правила «отклик за 100 мс» из `05-ui-system.md` |
| D-28 | Квиз подбора ослабляет условия, а не заводит в пустую выдачу | Строгая комбинация ответов легко даёт ноль моделей. Снимаются силуэт и размер, бюджет и форма лица — никогда: первое жёсткое ограничение пользователя, второе смысл подбора |

## Следующий шаг
Все восемь этапов регламента пройдены. Проект подготовлен к деплою на Netlify: `netlify.toml` в корне, конфигурация нулевая — Netlify определяет Next.js сам.

**Чтобы выложить:** запушить репозиторий в Git-провайдера и импортировать проект в панели Netlify. Подробности, ограничения и чек-лист перед боевым запуском — в `docs/07-handoff.md`, разделы 6 и 8.

**Вёрстка проверена в браузере.** Установлен headless-Chromium, написаны два скрипта (`scripts/`): 17 страниц × 2 брейкпоинта и 27 интерактивных сценариев. Проверка нашла семь дефектов, все исправлены — перечень в `docs/06-design-execution.md`. Два из них были содержательными: чекбокс фасета не отзывался до ответа сервера, а квиз подбора мог привести в пустую выдачу.

**Что осталось непроверенным:** реальные устройства, Safari и мобильный Chrome, скринридер, контраст, производительность.

**Требует живой проверки:** вёрстка в браузере на 390 и 1440 — в среде нет браузера, отклик сетки и мега-меню не проверены.
